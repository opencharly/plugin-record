# 2026.245.1333 — feat(record): record_env for VM/desktop recorder sessions + post-start liveness check

## Summary

Adds the `record_env` modifier to the `record:` verb so desktop (wf-recorder) recording works on VM/desktop venues, plus a post-start liveness check that turns false-positive starts into real failures.

**Why (measured):** on an omarchy VM, the autologin compositor session lives at `XDG_RUNTIME_DIR=/run/user/1000` with `WAYLAND_DISPLAY=wayland-1`. The recorder command previously hardcoded container defaults (`/tmp` + `wayland-0`), so wf-recorder exited instantly against the real session (the C1 spikes measured: record: start reported Recording started with NO process and NO file; the dead tmux session made record: stop fail with session not found).

**Changes:**
- `schema/record.cue` + generated `params/cue_types_gen.go`: `record_env` map (every stated key overrides the default, extras pass through; deterministic sorted+shellquoted `env K=V` prefix).
- `methods.go`: the wf-recorder command uses `recorderEnv(in)`; after the tmux spawn, `record: start` waits `recorderStartGrace` (named const, 1500ms) and verifies the session is alive AND the recorder process runs (pgrep) — an instant-exit recorder now fails start with a diagnostic.
- `methods_test.go`: `TestRecorderEnv` (defaults / overrides / extras / determinism) — green.
- candy description documents `record_env` for the marketplace/skills source.
