# 2026.254.0459 — sdk: land record stop/gif artifacts via sdk.LandArtifact (G-8/G-9)

## Summary

Migrate plugin-record's artifact handling to the shared `sdk.LandArtifact` entry point (plan G-8/G-9, sdk#249 merged at v0.2026254.439):

- `recordStop` (methods.go) — the manual `ex.GetFile(ctx, outFile, false)` → `os.WriteFile(in.Artifact, ...)` dance is replaced by `sdk.LandArtifact(ctx, ex, outFile, in.Artifact, op)`: reverse-channel pull → host write (with parent-dir creation) → `RunArtifactValidators(op)` ALWAYS runs inside the method, so the .cast event-count gate (`artifact_min_cast_events`) and the other shared validators fire at land time.
- `recordGif` (methods.go) — the identical GetFile → WriteFile dance is replaced by the same `sdk.LandArtifact` call.
- `op *spec.Op` is now threaded through `dispatch` → `recordStop` / `recordGif` / `sessionDispatch` so the validators read the desugared plugin-input map (the op crosses the provider boundary with the full #Op).
- The success-message shapes are preserved byte-for-byte ("Recording stopped (mode: …); saved N bytes to <path>" / "GIF rendered from …: N bytes written to …") via a post-land `os.Stat` — plugin-check's `writeRecordingsManifest` (G5) scans step logs for that exact format.
- go.mod: sdk require bumped v0.2026234.347 → v0.2026254.439; `go mod tidy` moved spec to v0.2026250.2036 (the sdk's own go.mod floor) and dropped grpc's stale `// indirect` marker.

No behavior change to the venue-driving core (tmux session lifecycle, graceful-stop probe, agg rendering) — only the artifact land+validate path.
